# 分享链接在微信内传播的合规风险评估

> 评估对象：`https://www.oictech.cn/games/mbti/`（「在朋友眼中，你的MBTI是什么？」）
> 评估日期：2026-09-18
> 依据文本：微信《外部链接内容管理规范》（更新日期／生效日期：2025 年 10 月 23 日）
> 来源标注约定：**「官方原文」= 规范逐字引用**；**「我的判断」= 本文档的分析结论**，二者不混用。

---

## 一、结论（先看这段）

**是，存在被处理的可能。但真正的风险点不是"诱导分享"，而是规范第 2.5 条——它把「性格测试」本身列为违规情形，不需要构成诱导分享即可成立。**

| 项目 | 结论 |
|---|---|
| 触发「诱导分享」条款（2.1） | 不构成（我的判断） |
| 触发「H5 游戏、测试类内容」条款（2.5） | **构成**（我的判断，条款逐字点名"性格测试"） |
| 触发「要求提供用户信息」条款（2.11.1 / 2.11.3） | 部分构成（我的判断） |
| 实际会不会被处理 | 取决于传播量与投诉量，不取决于内容本身（我的判断） |
| 最大业务风险 | **不是这个游戏被封，而是域名连坐** —— 见 3.1.5 |

**最需要知道的一件事**：规范 3.1.5 允许腾讯对**同一域名下的所有链接**采取措施。`oictech.cn` 上还挂着 `/wiki/`、`/fsl/`、`/ollama/`，一旦 `/games/mbti/` 被判违规且未整改，影响面是整站，不是这一个页面。

## 三、风险最高的两点

### (一) 2.5「H5 游戏、测试类内容」

**官方原文：**

> **2.5 H5游戏、测试类内容**
> 以游戏、测试等方式，吸引用户参与互动的，具体形式包括但不限于比手速、好友问答、**性格测试**，测试签、网页小游戏；

**我的判断：**

这是本次评估里唯一"内容本身就落在条款列举项里"的条款。它不要求存在诱导分享行为——只要形态是"吸引用户参与互动的测试"，就在条款射程内。本产品从命名到交互都是性格测试，无法通过改文案规避。

条款本身不是新增的，自 2018 年版规范就存在，在 2025 年 10 月 23 日更新版中保留。

**执行实况（公开报道，作为风险参照）：**

| 案例 | 处理结果 | 公开给出的理由 |
|---|---|---|
| 网易云音乐「主导色」性格测试 | 链接被停止访问 | "网页含游戏及互动测试内容，遭多人投诉，为维护绿色上网环境，已停止访问" |
| 「柏拉图」签名测试 | 公众号封禁 7 天 + 清除诱导分享所得关注 | 违反禁止发布测试类内容公告 |

**关键机制（我的判断）：**

处理触发条件是**投诉量**，不是内容相似度。网易云的案例里，腾讯给出的理由是"遭多人投诉"。也就是说：

1. 小范围流传（几十人、熟人之间点开）：被处理的概率低
2. 在朋友圈或群里刷屏、被多人投诉：被限制访问的可能性显著上升

---

### (二) 3.1.5 域名连坐

**官方原文：**

> **3.1.1** 腾讯有权对涉及上述违规情形的外链进行处理，处理措施包括但不限于限制相关链接在微信内直接打开、限制相关域名或IP地址在微信内的访问、停止相关链接在微信内继续传播、在朋友圈对相关内容做不可见处理等。
>
> **3.1.5** 如同域名下大量链接出现违规，经腾讯处理后仍未及时、有效整改的，腾讯有权视情节对该域名（含域名下的所有链接）采取处理措施。

**我的判断：**

这是本次评估里**后果最重**的一条。处罚的作用域是"域名"，不是"路径"。`oictech.cn` 上还有 `/wiki/`、`/fsl/`、`/ollama/` 三个业务，与游戏共用一个域名。

需要在决策时纳入的两点：

1. 若游戏被判违规且整改不及时，受影响范围可能扩展到整个域名
2. 把游戏迁到独立域名，可以把这一风险限制在游戏本身

## 四、次要风险

### (一) 2.11.3 要求用户提供 QQ 号码

**官方原文（节选）：**

> **2.11.3** 未经腾讯书面许可，通过微信服务收集、存储、抓取、获得或要求用户提供包括但不限于微信或其服务平台的信息内容、用户数据等腾讯认为属于敏感信息范畴的数据（包括但不限于微信账号、微信密码、**QQ号码**、QQ密码、用户关系链、好友列表数据、银行账号和密码等）……

**我的判断：**

条款把「QQ号码」明确列举为禁止"要求用户提供"的数据。注册表单把 QQ 号作为账号选项之一，字面上落在这条里。该条的适用前提是"通过微信服务收集"，用户手动填写是否落入这一前提存在解释空间，但把「QQ 号」从表单里去掉的成本接近零。

### (二) 2.11.1 注册才能使用功能

**官方原文：**

> **2.11.1** 未经用户明确同意，并向用户如实披露数据用途、使用范围等相关信息的情形下复制、存储、使用或传输用户数据的，包括但不限于：要求用户共享个人信息（手机号、出生日期等）才可使用其功能……

**我的判断：**

条款的免责前提是"用户明确同意 + 如实披露用途"。当前注册弹窗已有以下披露，构成该前提：

- 「我们买不起短信验证／邮箱验证服务，因此请务必妥善保存登录账号和密码。」
- 「收集这些信息仅用于让你日后登录查看自己的测试结果，我们不会使用、也不会主动泄露你的任何个人信息。」

条款列举的是"手机号"，当前账号字段为邮箱／手机号／QQ 号三选一，非强制手机号。这一点上风险可控。

### (三) 2.18.4 备案号未展示

**官方原文：**

> **2.18.4** 未按照法律法规规定履行备案手续或难以追溯网站运营者真实身份的网站链接；

**我的判断：**

已核查 `/var/www/oictech/` 全站（含所有 HTML／JS／CSS），**未发现任何「ICP 备」「备案号」「beian」字样**。域名解析到境内腾讯云主机且 80／443 可用，按腾讯云的前置要求，域名本身应已完成工信部备案；但**页面未展示备案号**，与《互联网信息服务管理办法》的展示要求不符，也在形式上落入 2.18.4 的"难以追溯运营者真实身份"。

第三方备案查询（站长工具）对 `oictech.cn` 未返回数据，建议在工信部备案系统（`beian.miit.gov.cn`）自行核实一次并保留截图。

## 六、我的整体判断

**（以下均为我的判断，非官方表述）**

1. 单纯生成分享链接、发给朋友填写，**不构成诱导分享**。产品没有任何"分享后才能看结果"的门槛，也没有任何奖励机制，2.1 全条不成立。

2. 但从"内容形态"看，这个产品落在 2.5 的列举范围内，这一条不因文案优化而消失。

3. 是否被处理，主要取决于**传播规模与投诉量**。熟人之间几十人使用，被处理的概率低；在朋友圈或群里形成刷屏并被多人投诉，风险明显上升。

4. 真正需要提前安排的是**风险隔离**，而不是文案：把游戏与其它业务分域，或者接受"整站共用域名"这一前提并接受相应后果。这一点值得在继续传播之前定下来。

5. 上述第 1、2 条建议（去 QQ 号、补备案号）成本很低，建议直接执行。

## 附录一：ICP 备案的公开暴露范围（回答"会不会被开盒"）

### 工信部公共查询会显示什么

访问 `beian.miit.gov.cn` → 公共查询 → 备案信息查询，按域名或备案号检索后，公开可见字段为：

| 字段 | 说明 | 是否涉及个人隐私 |
|---|---|---|
| ICP 备案号 | 如「京ICP备XXXXXXXX号」 | 否 |
| **主办单位名称** | **企业备案 = 公司全称；个人备案 = 本人姓名** | **取决于备案主体性质** |
| 主办单位性质 | 企业 / 个人 / 事业单位等 | 否 |
| 网站名称 | 备案时填写的站点名 | 否 |
| 网站首页网址 / 域名列表 | 该备案号下挂的全部域名 | 否 |
| 审核通过时间、备案审核部门 | 如「北京市通信管理局」 | 否 |

**关键结论（我的判断）：**

1. **身份证号、手机号、家庭住址一律不公开。** 多个来源一致：公共查询"不会显示完整证件号"。这是"开盒"所需的最高价值字段，备案渠道拿不到。
2. **真正需要确认的只有一项——「主办单位名称」显示的到底是公司还是你本人。**
   - 若 `oictech.cn` 是**企业备案** → 公开的是公司全称（页面上本来就写着 OIC Technology），**你的个人姓名不出现**
   - 若是**个人备案** → 该字段就是你的姓名，且**可以被任何人按域名查到**
3. **姓名被公开 ≠ 被开盒。** 开盒需要"姓名 → 手机号 / 住址 / 身份证"的聚合。备案只提供姓名这一个环节，其余环节它不提供。风险主要是"可被关联"，不是"信息完整泄露"。
4. **第三方站长工具会抓取并缓存备案数据**，且聚合展示解析 IP、服务器归属地、历史备案等。它们能把"域名 → 主体名称"这一步做得比工信部更方便，但拿不到工信部没有的字段。
5. 有第三方来源提到"网站负责人姓名"也可查。工信部官方公共查询的主体字段是「主办单位名称」；第三方平台展示口径不一。**以你实际查询时页面显示为准。**

### 自查清单（做备案查询时顺手核对）

1. 记录「主办单位性质」字段：企业 / 个人
2. 若为**个人**，记录「主办单位名称」是否全文显示、还是打了星号
3. 若为**个人且全文显示姓名**，可考虑的选项：
   - **变更备案主体为企业**（最彻底；需要企业营业执照，且该企业需与你有关联）
   - 保持现状并接受"姓名可被按域名关联"这一事实
4. 注意 `.cn` 域名的 WHOIS 与 ICP 备案是**两套独立**的信息，WHOIS 有隐私保护不代表备案也脱敏
5. 公安联网备案（`beian.gov.cn`）是第三套信息，展示口径与工信部不同，若已办理需一并核对

### 与微信外链的关系

备案主体是个人还是企业，**不影响**微信外链规范 2.5（测试类内容）的判定。它影响的是规范 2.18.4「难以追溯网站运营者真实身份」——**页面展示备案号**才是那条的对应动作，与主体性质无关。
